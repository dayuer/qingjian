# 旧库为什么在对话上强（2026-10-08）

旧库、新库、含章·通变都没见过）；sentences.tsv 与冻结回放 `--clean2` 作辅助。**只做分析，没有在外部集上挑任何参数。**

## 一、差距几乎全在语言模型

旧 / 新 dict 与旧 / 新 lm 交叉成四格（外部集，首选 / 前三 / 字准）：

| | 旧 lm | 新 lm |
| --- | --- | --- |
| 旧 dict | **58.9** / 62.4 / 90.9 | 52.5 / 58.3 / 88.9 |
| 新 dict | 58.0 / 61.3 / 90.6 | 52.2 / 58.0 / 88.7 |

换 lm 差 5.8–6.4 个点，换 dict 只差 0.3–0.9。下面的分析都固定新 dict、只比两份 lm。

## 二、逐条：旧 lm 对、新 lm 错的 171 句（反过来 69 句）

正确句与新 lm 的首选都按读音对齐切成词库词，再用 `crates/qingjian-lm/examples/lm_probe.rs` 查两份 lm 里路径上每个二元：

| 原因 | 条数 | 例子（正确 ← 新 lm 首选，关键二元） |
| --- | --- | --- |
| 二元搭配缺失：正确路径上的某个二元旧 lm 有、新 lm 没有 | 89（52%） | 分的餐馆吃酸奶 ← 分的参观吃酸奶（餐馆→吃）；周边有什么景点呢 ← 周边有什么经典呢（有什么→景点）；该景点周边都有什么酒店呀 ← …酒店亚（酒店→呀）；这个餐馆的附近… ← 这个参观的附近…（这个→餐馆） |
| 同音词概率排反：切法相同、二元都有，新 lm 把错的排前 | 51（30%） | 元的餐馆 ← 元的参观；有叫醒服务吗 ← 又叫醒服务吗；我有点事要问 ← 我有点是要问；北京万达文华酒店 ← …文化酒店；有啥景点 ← 有啥经典 |
| 切分偏好不同 | 22（13%） | 报销范围 ← 包小范围；包含接机服务 ← 包含街及服务；留着备用 ← 留着呗用 |
| 新首选切不开（英文、生成） | 9（5%） | 渔夫烤鱼 ← 预付卡与 |

一半以上是**口语场景的搭配新 lm 没见过**（餐馆→吃、这个→餐馆、酒店→呀），三成是**一元先验偏向书面词**（参观 / 经典 / 文化 压过 餐馆 / 景点 / 文华）。

## 四、配方对照

- **lm 的生成方式两版相同**（`tools/dict-convert/src/bigram.rs`）：按词库做一元最大概率分词，只统计连续汉字段，统计一元与二元计数，
  按计数截到上限（10-07 的 4545bd0 才把缺省从 300 万提到 500 万，对齐旧库的 486 万条）。平滑都是运行时固定 λ = 0.8 的插值。
- **差在语料构成**。旧库：完整 LCCC（含模板刷屏，对话 : 书面 ≈ 63 : 1，见 1c 的统计）+ 维基。新库（10-08 00:04）：
  坏去重后只剩 59 万行的 LCCC × 10 + 清洗过的维基。对话 token 少了一个数量级以上，二元又是全局按计数截断，口语二元被维基二元挤出了表。
- dict：条数相近（93,238 对 91,801），对外部集的影响不到 1 个点。旧 dict 的分位数没有逐条复原（旧库只有 .qj），影响小，不展开。

## 五、怎么在新管线里复现这些长处

1. **对话 token 量补回来**：用 1c 重做的 LCCC（1987 万行、去模板）重建 lm。验收前先看第三节那张表：吗 / 呢 / 吧 / 呀 / 你 的一元 log 概率
   回到旧 lm ±0.3 以内，日至 / 参见 不高于旧 lm。这张表是不碰评测集的语料自检。
2. **二元按语域分开截断**：全局按计数截 500 万时维基二元占绝大多数。改成对话、书面各自取前 N（或按语域配额）再合并，
   保证 餐馆→吃、这个→餐馆 这类低频但成片的口语搭配留在表里。
3. **维基模板与日期片段不进计数**：日至、参见 这类在统计层挡掉（数字相邻的片段不计、模板行剔除），1c 已在做。
4. **不需要改引擎**：四格里引擎相同，差距全在数据。KN 平滑、修正量、融合这些引擎侧改进都应在新 lm 补齐之后再叠加评估。

复现命令：交叉四格是把两份产物的 dict.qj / dicts 与 lm.qj 换着链进 `data/generated`，`qingjian-cli --eval-text data/eval/external-frozen.tsv --eval-details …`；
逐条归类脚本与探针输出在 bug修复大师 工作区 `.lab/tools/why_old.py`（不入库）。

## 六、语域插值（1c 的对话 / 书面两套，2026-10-08）

1c 按语域分开建的两套 lm（对话 `193cb324`、书面 `ce370499`，共用混合那套的 dict `94f2a91f`）用 `sentence::RegisterMix` 插值，
参数只在两份开发集上定（首选；旧库一行作对照）：

| | 外部集 | sentences.tsv | 对话留出 | 书面留出 | clean2 回放 词 / 整句 |
| --- | --- | --- | --- | --- | --- |
| 旧库 | 58.9 | 34.2 | 64.1 | 52.8 | 915 / 96 |
| 只用书面 lm | 27.1 | 31.6 | 29.1 | 54.4 | 882 / 87 |
| 只用对话 lm | 54.6 | 25.2 | 64.8 | 20.8 | |
| 语域插值 | 57.3 | 34.1 | 61.9 | 53.2 | 900 / 92 |

书面一侧插值超过旧库，对话一侧（外部集）还差 1.6。外部集上旧 lm 对、对话 lm 错的 118 句里，切分偏好 46、二元缺失 44、切不开 24，
例子集中在实体名（锦江之星、日坛公园、经济型、会议室、天安门广场）。起初归因为「两份语料分开统计、跨语域二元哪份都没有」，**这是错的**：
二元只在同一行里统计，拼接语料也不会产生跨文件的二元。1c 查证的真实原因是**新 dict 缺这类实体词条**（日坛公园、锦江之星、经济型、会议室
在混合那套的 dict 里都没有，旧 lm 里有日坛公园），分词切不出它们，相关二元自然也没有；R3 加的语料门槛把它们推进了缺省关闭的包。
1c 已修门槛并用维基标题补地标与机构名，这部分等新词库出来再量。
