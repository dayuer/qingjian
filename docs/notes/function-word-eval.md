# 虚词判别器的离线可行性（2026-10-10）

问题：整句首选里 的 / 得 / 地、在 / 再、是 / 时 / 事 这几类同音虚词错得多（5000 句里约 2.5% 的句子），调二元预算修好与误伤约 1 : 1.7，
通变融合也只修好 2 句。设想是整句解码完之后加一个小判别器：用户已经打完整串拼音，虚词右边的词是知道的，用左右各一两个词在集合内重选。
结论：**离线就没过判据（修好 / 误伤 ≥ 3 : 1 且净修好 ≥ 集合内错误的 30%），B 上净修好只有 5.6%，没有进 Core。**
他 / 她 / 它 是指代与性别问题，不在这次范围。为什么二元分不开这几类，见 [homophone-bigram-limit.md](homophone-bigram-limit.md)。

## 一、协议

- **留出集**：沿用词库线的 20 万句挖错集（`lccc-lm90` / `zhwiki-lm90` 各抽 10 万个汉字片段，与所有评测集不共享 8 字片段），
  其中带拼音的 140,389 句按句子哈希分成 A（70,296）/ B（70,093）。**A 调参，B 只出数**。
- **训练语料**：`lccc-lm90` + `zhwiki-lm90` 按行哈希抽样，对话 1803 万字 + 书面 1592 万字，453 万个片段。整行剔掉的有两类：
  含任一留出片段的 17,898 行，与评测集共享 8 字片段或整段就是评测句的 106,669 行。断言 A、B 每一句都不在训练片段里，通过。
  找留出片段前**先去掉空格**：LCCC 是空格分词的，在原行上找会漏掉跨空格的片段。
- **解码器**：产品解码器（sujian `2d4ffd5` + 随包数据 dict `0c24a7ae` / lm `94d18e77`，`tools/eval/offline.toml`，开成语包），
  A、B 各解一遍；B 另用通变 8 位融合解了 6430 句的子集。
- **判别器**：每个集合一个多类逻辑回归，特征哈希。特征有四组：
  - 目标字左右各 3 个字与字二元；
  - 左右各 2 个词。目标字两侧分开切词，所以特征不依赖当前是哪个字，原文与解码结果用同一套；
  - 左右词的组合；
  - 每个候选字与左右邻字能不能成词表里的词（地图、当地、时间、目的）。

  解码出的字落在集合里就触发，判别器的首选比当前字高出 τ 才改。τ 只在 A 上扫，取「修好 : 误伤 ≥ 3」里净修好最多的一档。
- **口径**：「集合内错」= 解码字与原文字同属一个集合但不同，判别器都够得着；有一边不在集合里的另记，判别器改不对。

## 二、数字（B，不带模型，τ 在 A 上定：的 8.0 / 在 2.5 / 是 3.0）

| 集合 | 触发位置 | 解码准确率 | 判别后 | 集合内错 | 修好 / 误伤 | 净修好 / 集合内错 |
|---|---:|---:|---:|---:|---:|---:|
| 的 得 地 | 22,297 | 94.59% | 94.69% | 1206 | 29 / 7 | 1.8% |
| 在 再 | 5,691 | 93.97% | 94.52% | 343 | 49 / 18 | 9.0% |
| 是 时 事 | 13,697 | 95.88% | 96.35% | 565 | 89 / 24 | 11.5% |
| 合计 | 41,685 | 94.93% | 95.21% | 2114 | 167 / 49 | 5.6% |

修好涉及 167 句、误伤涉及 49 句。在 / 再 的比值 2.7，连 3 : 1 都不到。

融合子集（同一批 6430 句）：不带模型净 3.5%，融合净 3.1%，模型开着判别器也没更有用。

## 三、为什么不行

1. **上限低。** A 上 τ = 0、完全听判别器时，的 / 得 / 地 修好 399、误伤 496，在这些位置判别器本身就不如解码器。
   整句 Viterbi 已经用到右邻词的二元，左右 ±2 词的线性窗口没多出多少信息，在解码器错的那些难例上它同样错。
   词类特征（Brown 聚类）没加：上限已经说明窗口特征不够，加词类改变不了量级。
2. **只在解码器自己拿不准时改，覆盖太小。** 限定「只换这一个字的整句也在解码器候选前几名里」，精度上去了，但够得着的位置太少，A 上净修好最多 8%。
3. **答案本身脏。** B 的集合内错里对话 1537、书面 577，的 / 得 / 地 光对话就 955。聊天原文大量写「跑的快」「来的好突然」，
   判别器改成规范的「得」反被记成误伤。用户自己就这么写，输入法照用户习惯出字不算错，这部分归个人学习；
   按对话原文当答案量 的 / 得 / 地，上限被参照本身压住了。

## 四、以后

- 的 / 得 / 地 真要攻，先按规范用法另标一个书面小评测集，再谈判别器或别的办法（见 `docs/plan/todo.md`）。
- 是 / 时 / 事 与 在 / 再 单看有一点量（B 上净 11.5% / 9.0%），但离 30% 远，不值得为它们单独进 Core。
- 实验脚本（抽语料、切词、特征、训练、评测）没有入库；要复现按第一节的协议重写。
