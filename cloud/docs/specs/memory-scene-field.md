## 一句话

`MemoryItem.scene` 与 `ContactRegistration.scene` **请删掉**（proto 里、存储里、接口里都不再需要）。
客户端不再传，服务端也不再收。

## 为什么

客户端 2026-10-05 把「场景」这一层**整个去掉了**。经过是这样：

1. 原来是写死的三个（恋爱 / 日常 / 工作），三个场景行为还不一样；
2. 当天先改成「用户自己建、自己起名、可改可删的分组」（`memory/scenes.json`）；
3. 当天又推翻：「没有场景了，人是一张平铺的名单，键盘上左边切人、右边切技能」。

现在的形态：

- 名单就是一张平铺的人（`contacts.json`），**没有分组**；
- 键盘工具栏左边切人、右边切技能；**每个人可以指定一个改写技能**（`Contact.skill`，不指定就用全局默认）；
- 学习不再按场景分区，改成**按人隔离**：选了人时学到的只进这个人的对象层（不写全局、不记个人 n-gram），
  「不指定」时才写全局；
- 「按场景开记录」（设计稿 05 的 2f 那三个开关）作废，**上传同意改成全局一个开关**（2026-10-05 用户定）。

## 请服务端做的

1. `MemoryItem.scene` 与 `ContactRegistration.scene` **删掉**（proto 定义、入库、接口文档一并）。
   如果服务端想留着字段不接，那也行——**客户端不会再传**，服务端不该按它做任何分支。
2. 存储与脱敏规则里如果用了它（分区、计费、脱敏），要改成不依赖；**没有任何东西能替代它**：
   「记的是哪一类关系」已经没有这个信息了，不要从别处猜。
3. 历史数据里的 `daily` / `dating` / `work` 随它去，不用迁——客户端这边对应的 `scenes.json` 已经删了。
