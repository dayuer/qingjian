# 打字内容的 AI 优化：规格（2026-10-06）

**状态：草案，待审计会话审，审过交服务端实现。** 用户已定：打字内容全部同步到云服务（开关于
`input_log`，见客户端实现），交给 AI 优化。这份回答「优化什么、怎么跑、边界在哪」。

## 一、优化出什么

**个人短语包**（主要产物）与**纠错对**（次要），都走 learning 下行同步回键盘，不发明新通道：

1. **短语包**：从输入日志的高频 n-gram 里挖「打了不止一次、每次都整段接受」的串，生成
   `phrase` 类型的学习条目（复用 `LearningPush` 的既有类型：词、码、频次）。例：用户一周里
   七次打出「周三下午 Standup 前把报表发我」，生成一条自定义短语。**只挖 ≥6 字的整段重复**，
   短于它的交给本地学习就够（Core 已有 n-gram 与自动造词），云端不抢本地能干的活。
2. **纠错对**：复用 tuner 现成的纠错闭环产物（`user-typos` 那套 (敲的, 要的) 对），AI 只负责
   从日志里把「同一串敲错又改回来」的模式找齐、去噪，不新增数据形态。
3. **不产出**排序权重。排序插值（个人 n-gram、choice_weight）是 Core 本地能力，云端下发权重
   会让两端模型漂移、没法本地验证。明确排除。

**同步回键盘**：learning 包的下行（`GET /v1/learning`，键盘已有合并逻辑），不另开口子。
下行的条目带 `origin: "cloud-optimizer"` 标记（proto 的 LearningEntry 加一个可选字段），
用户在 Mac / iOS 的学习管理里能看到「这是云端替你学的」，可整体关掉（`sync` 开关本来就管）。

## 二、什么时候跑

**每日一次，与 learner 同一套调度**（`SUJIAN_LEARNER_ENABLED` / `SUJIAN_LEARNER_HOUR`），
不单独设开关时段。learner 线上目前是关的——**这项优化跟着 learner 的门槛走**：
客户端同意页上线 + 用户点头后才部署打开，同一个动作，不拆两次决策。

## 三、脱敏（硬门槛）

送大模型之前**必须**先过 `qingjian-cloud-redact` 的规则层（`redact_rules`，与服务端共用同一
份向量测试），规则层漏检的再过一遍服务端现有的 deid 检测。两层都过了才出网。任何一层命中，
该片段整体替换为占位符后再送——**不因为脱敏命中就跳过优化，也不送原文**。

## 四、成本上限

沿用 `SUJIAN_MEMORY_DAILY_TOKENS` 的思路，新增 `SUJIAN_OPTIMIZER_DAILY_TOKENS`
（缺省 200k/用户/天）：按用户、按自然日（UTC+8）封顶，超了当天不再跑、也不滚存。
模型沿用记忆整理那套（DeepSeek，`SUJIAN_MEMORY_LLM_*` 同一组配置），不单独配。

## 五、云端保留多久

**输入日志原文 7 天**，与素材同规矩：上传后 7 天内被优化任务消费，过期未消费的删除；
优化产物（短语、纠错对）无「过期」概念（它们是学习数据，走 learning 删除链路）。
用户点「清空云端输入记录」（客户端已实现）随时全删，优化产物**不**跟着删——
那是已经学到的能力，删它走学习管理的既有入口。

## 六、隐私边界（与同意文案对齐）

- 客户端同意页已写明：打的字上传到素笺的服务器（新加坡）；优化时脱敏后发给 DeepSeek（中国境内）。
- 密码 / 验证码 / 电话 / 数字键盘的输入在客户端就不记（`MutedLogger`），永远不会到服务端。
- 优化任务只读输入日志，不碰 memory 素材（那是 2C 的地盘）与剪贴板。
- 审计：每次优化任务记一条运行日志（条数、token 用量、命中脱敏的次数），线上可查。
