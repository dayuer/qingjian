# 上下文预测：按上文排候选与本地 Tab 续写（2026-10-04）

只在素笺的 `sujian` 分支做，不提交上游。对上游文件的改动按 [fork-patch.md](../fork-patch.md) 的做法：新代码放新文件，旧文件只加挂钩，每处记一行。

## 问题

同样敲 `youxiang`，「汽车」后面要「油箱」，「我现在」后面要「又想」，现在两种情况首选多半一样，想要的词常在后面。原因（代码核对过）：

1. 词级排序只认本会话上一个上屏的词（`CommitChain`），宿主光标前的文字不进词级排序；遇到标点、切应用就回到句首（`query/phonetic.rs:155`、`commit/chain.rs:36`）。
2. 排序键里「同一输入串下选过的次数」（choice）排在语言模型分之前（`ranking/scored.rs:76-87`），选过一次「邮箱」，上文怎么写都是它第一。
3. 桌面默认的神经模型是「含章·通变」，只看按键、不看上文；看上文的「含章·知微」默认不加载（`apps/macos/src/host/model/mod.rs:24`）。神经重排也只排整句路径，不排词级候选。
4. 「又想」不是词库词，只能以整句「又 + 想」出现，和词级首选比分吃亏。
5. Tab 续写只有云端（`[predict]`，缺省关，300 ms 消抖加网络往返）。

## 目标与验收

- 新评测集「同拼音不同上文」（≥300 对）上，**词级首选命中率**比现状提升 ≥15 个百分点；`--eval-text` 整句首选与 `--replay` 词首选的下降都不超过 0.5 个百分点。
- 按键路径不变慢：重排与续写都在停键后异步做，按键同步部分的 p99 不超过现状 +1 ms。
- 本地续写：评测集上「显示了就接受」的代理精度（续写前缀与真实下文一致 ≥2 字）≥60%，p90 时延 ≤150 ms（M 系列 Mac）。
- 平台：macOS 全做；iOS 只做不需要模型的部分（第 1、2 项），模型部分等 iOS 内存实测。Windows、Linux 不在素笺范围。

## 设计

### 第一阶段：按上文重排

1. **宿主前文接进词级排序。** Engine 已有的前文入口（macOS 组句第一键读 64 字，`set_rescoring_context`）同时喂给词级排序：
   会话链为空（句首）且前文非空时，用语言模型对前文末尾 8 个字做最大匹配切词，取最后一到两个词作为 `Context`，参与 `transition_log_prob`；
   整句 Viterbi 的第一个词也用这个 `Context` 而不是 `Context::START`。会话链非空时仍以会话链为准。
2. **「选过」改为加分。** 排序键里去掉 `choice` 这一级，改成在分数里加 `β · ln(1 + choice)`；β 用 `--replay` 扫出来，要求 `--replay` 不降，并写成常数。
3. **知微给词级候选按上文打分。** 停键 80 ms 后（与现有整句重排同一条异步通道），对第一页前 6 个词级候选与整句首选，用 `CharScorer(前文, 候选)` 打分，
   按 `静态分 + λ_w · (神经分 − 静态分)` 重排第一页；λ_w 用新评测集扫。结果晚到就不动已经显示的页（与现有重排一致：到了再查一次重画）。
4. **模型加载。** 新配置 `[model] scorers = "both"`（素笺缺省）：通变照旧排整句路径，知微负责词级上文打分与续写；内存约 +56 MB。`"tongbian"` 即现状。

### 第二阶段：本地 Tab 续写

5. **续写接口。** `qingjian-neural` 加 `continue_text(before, max_chars) -> Option<(String, f32)>`：知微贪心解码，遇标点或 `max_chars`（缺省 8）停，返回续写与平均对数概率；复用 `PrefixCache`。
6. **触发与显示。** 第 3 项重排完成后，以「前文 + 当前首选」为条件续写；平均对数概率低于门槛 τ 就不显示。显示与接受复用云端整句补全的现有通道（macOS preedit 右侧灰字、Tab 接受，`imk/controller/display.rs:128`、`command.rs:74`）；
   本地续写先到先显示，云端结果只在本地没有续写时显示。接受后照云端补全的做法切词记进个人 n-gram。
7. **门槛与时延。** τ 用续写评测扫，按「代理精度 ≥60%」取；单次续写超过 150 ms 就放弃本次。

### 评测

- `data/eval/context-pairs.tsv`：`拼音\t前文\t期望`，同一拼音至少两条不同前文，≥300 对，人工整理、不含真实用户数据；覆盖同音词（油箱 / 邮箱 / 又想、公式 / 公事 / 攻势 …）。
- CLI：`--eval-context <tsv>` 报告有前文 / 无前文两种设置的词首选命中；`--eval-continuation <文本>` 在留出文本上逐位置续写，报告代理精度、平均长度、p50 / p90 时延。
- 每一步合入前跑：`--eval-context`、`--eval-text`、`--replay`（用作者本人的输入日志）。
