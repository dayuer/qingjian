# 场景与关系记忆

2026-10-04 起草，未实现。基于青简分叉做的「关系记忆」产品：输入法里用户可以建「聊天对象」，
每个对象在云端有独立的数据分区和一份长期记忆，打字时提示与这个人有关的事。

> **2026-10-05 改了场景与分区学习。** **没有场景了**：那份「用户自建的分组」（`memory/scenes.json`）也是过渡形态，
> 当天又去掉了——名单就是一张平铺的人，键盘上左边切人、右边切技能（[人 + 技能包](../plans/2026-10-05-people-and-skills.md)）。
> 分区学习改成**按人**：选了人时写只进这个人的对象层（不写全局、不记个人 n-gram），没选人（「不指定」）才写全局。
> `Scene = 人设 + 学习分区 + 云功能开关` 那句一并作废。「人设包 Persona」是另一件事（云端下发、带版本），仍未实现；
> 与它形式上相近的[改写技能包](rewrite-skills.md)是**本地**的、只管按一下改写这一段话，两者不要混。

架构是**云端学习、本地使用**：素材上传到云端，按分区隔离存储，脱敏后只在分区内部学习；学好的人设包与用户包（每个对象一份）
同步到本地加密保存，打字时的联想、叠加学习、记忆提示全在本地完成，不逐次调云。
基础输入（拼音、词库、整句、基础学习）沿用青简，不依赖云。

## 目标与边界

- **长期记忆的养成**：聊得越久，输入法越懂「我和这个人」——对方的生日、喜好、忌口、最近在忙什么、我们约好的事。
  记忆是关于对方与这段关系的，用户随时能看、改、删。
- ~~**场景不串**~~（2026-10-05 改成**按人不串**：场景只是分组，没有场景学习层了；选了人时学到的词只进这个人的对象层，
  换个人或「不指定」都看不到；「不指定」时写的才是全局）。
- **输入优先**：打字不等网络。切换人设 / 对象是本地操作，组句、联想、提示全用本地已同步的包；素材异步上传；
  断网时用上次同步的包照常工作，只是不再长新记忆。记忆提示不进候选列表、不弹窗、不阻塞组句。
- **云端分区隔离**：每个用户、每个场景、每个对象一个分区，分区之间在存储与检索上互不可见；静态数据用客户端持有的密钥加密。
- **脱敏后学习**：素材进入记忆与学习之前，先由大模型去掉直接标识（真实姓名、电话、地址、证件号、账号），只挂在随机的对象 id 下。
- **只做分区内部学习**：每个分区只用自己的数据学，不跨分区、不跨用户，不训练任何共享模型。

不做（产品原则，不是暂缓）：

- **不读聊天窗口。** 不用 macOS 辅助功能 / Windows UIA / AT-SPI 抓对方的消息或联系人名。对象由用户手动切换，对方说了什么只能由用户主动「记一笔」。
- **不做说法一致性检查。** 不比对「我对 A 和对 B 说的有没有矛盾」，不提示为维持说辞服务的内容。记忆提示围绕对方与双方的约定。
- **不做批量与协作。** 没有共享话术库、多账号共享对象、批量导入对象、开放 API。
- **不跨用户学习。** 用户数据不进任何共享模型，也不做聚合统计反哺人设；官方人设包的初始内容由运营编写，与用户数据无关。

## 数据流：云端学、本地用

```
                    打字（全本地）
用户 ──上屏──▶ Core：基础学习 + 叠加当前人设包 / 用户包 ──▶ 候选、联想、提示行
  │                                        ▲
  │ 素材（发出的话 / 记一笔），异步、可排队    │ 解密后加载
  ▼                                        │
云端 /ingest ──▶ 脱敏 ──▶ 分区内抽卡与学习 ──▶ 打包 ──同步──▶ 本地加密包
```

- **打字时不调云**：联想、叠加学习、记忆提示都只读本地包。云端只在两件事上出现：异步收素材，以及把学好的包同步下来。
- **切换是本地操作**：选「小美」就是加载本地的「小美」用户包，毫秒级，不需要网络。
- **同步时机**：启动、每天学习批处理完成后的推送通知，以及推送丢失时的兜底（每 6 小时查一次版本）；都在后台线程，不阻塞输入。
- **断网**：用最后一次同步的包照常工作；素材在本地加密队列里排着，联网后补传。
- 对象只能手动切。切到对象后状态条醒目显示对象名或代号，这是防止「对着 A 用了 B 的包」的唯一保障；
  应用切走再切回保留上次的对象，状态条闪一下提醒确认。

### 包的内容

| 包 | 内容 | 大小量级 |
|---|---|---|
| 人设包 | 官方底包（话术词库 `.qj`、语气说明、皮肤）+ 该用户在这个人设下的分区学习表 | 底包 1–5 MB，学习表 KB 级 |
| 用户包 | 对象分区的学习表（词频 / 用户词 / n-gram，与 `FrequencyLearner` 同构）、记忆卡、提示关键词索引、今日提醒 | 几十到几百 KB |

- **学习节奏**：每个分区每天学一次（用户本地时间凌晨批处理），当天的素材第二天进包；记一笔与手动改卡即时生效于本地包，不等批处理。
- **打包范围**：学习表只打包最近 90 天的数据加全期高频部分（高频门槛待用回放数据定）；记忆卡全部打包（量小）；更早的明细只留在云端分区里。
- 包带版本号，同步走增量：云端按版本差给补丁，失败退回整包。
- 两台设备都在上传素材时不会冲突：学习只发生在云端，本地包只读，以云端最新版本为准。
- 记忆卡在本地改 / 删：先改本地包立即生效，同时发 `PUT/DELETE /cards`，下次同步以云端结果覆盖。

## Core 的改动（可提上游）

Core 不知道云，也不知道包从哪来，只接收壳解密后交给它的数据：

- `LearningScope { path, inherit_global }`：学习分区标识；`Engine::set_learning_scope` 在切换时调，丢掉在飞的云结果与前文（同 `set_private`）。
- `OverlayLearner`：包住现有的 `Box<dyn Learner>`（与 `learning::MutedLearner` 同样的套法）。读时把包里的学习表叠加在本地学习之上，
  叠加层权重放大（常数用 `apps/cli` 回放调）；叠加表只读。写时本地全局学习照常（工作场景可关），同时把这次上屏交给一个回调，由壳放进上传队列。
- `PersonaSpec { dictionaries, boost, style }`：`Engine::set_persona`；词库复用 `set_extra_dictionaries` 的路径，`style` 只给可选的云端改写用。
- `HintIndex`：记忆卡的关键词索引，组句中与刚上屏时用当前文字匹配，分数过线才给提示行；纯内存查询，预算与候选生成同级（亚毫秒）。
- 私密输入（`set_private`）优先：私密时不叠加、不提示、不回调。

上游青简可以用同一套接口做纯本地的场景（叠加表来自用户自己的文件），分叉的不同只是包由云端学好再同步下来。

## 记忆

### 来源

1. **我发出的话**：当前对象下上屏的文字，按「一次发送」聚合（回车上屏或停顿 > 30 秒为界），异步上传到对象分区。私密输入不传。
2. **记一笔**：用户选中（或复制）对方的一条消息，按 `[shortcut] memory_note` 上传。这是唯一获得「对方说了什么」的途径。
3. **手动卡片**：在管理界面直接写。

上传前客户端先做一遍规则脱敏（手机号、身份证号、银行卡号、邮箱），云端再做大模型脱敏，两道都过才进分区。

### 脱敏管线（云端）

```
素材 ──▶ 规则层：正则识别证件 / 卡号 / 电话 / 邮箱 / 地址 → 占位符
     ──▶ 模型层：大模型识别人名、单位、具体地点、能定位到个人的细节 → 占位符或泛化（「在腾讯上班」→「在互联网公司上班」）
     ──▶ 校验层：第二次规则扫描，命中则整条丢弃并记数（不记内容）
     ──▶ 抽取：生成 / 更新记忆卡
     ──▶ 原文：处理完即丢弃，不入库
```

- 对象本人的称呼不进云端：对象名字只在客户端显示，云端只有随机 `contact_id`；用户给对象起的名字也用私钥加密后存。
- 大模型脱敏会漏，所以规则层在前后各做一次，且原文不入库，漏掉的风险只停留在一次请求的内存里。
- 记忆卡本身要保留「生日 3 月 14 日」「不吃香菜」这类关系事实，这类不属于直接标识，不脱。

### 记忆卡

```rust
pub struct MemoryCard {
    pub id: CardId,

    pub kind: CardKind,               // Fact / Preference / Date / Plan / Promise / Topic

    /// 一句话，能直接显示在提示行，例如「不吃香菜」。
    pub text: String,

    /// 日期类卡片的日期；Plan / Promise 的到期日。
    pub when: Option<Date>,

    /// 用户确认过的卡排序更高；云端抽出来未确认的卡带「待确认」标记。
    pub confirmed: bool,

    pub created: Date,

    /// 最近一次被提示或被用户确认的时间，用来做衰减。
    pub touched: Date,
}
```

`Promise` 是双方的约定（「答应周末陪她看电影」「她说下次请我吃饭」），到期前提示，是「养成」里最有温度的部分。

### 养成循环

```
上屏 / 记一笔 ──▶ 云端脱敏 ──▶ 抽取 ──▶ 新卡（待确认）/ 更新已有卡
                                              │
            管理界面「这周记住的」：确认 / 改 / 删 ◀┘
                                              │
                        同步进本地用户包 ◀┘
                                              │
                    打字时提示 ──▶ 点了或忽略 ──▶ 回传 touched / 降权
```

- **确认是养成感的核心**：每周一张「这周我记住了她的这些事」，确认一条记忆就牢一点；不确认的卡 30 天后淡出（降到最低，不删）。
- **合并**：同一件事的新信息覆盖旧卡并保留历史（「喜欢猫」→「养了一只猫叫团子」），是对对方信息的更新，不是对用户自己说法的一致性检查。
- **衰减**：长期没被提示也没被确认的卡降权；日期类卡不衰减。

### 提示

- **提示行不是候选**：候选窗下方一行，灰色，最多一条；快捷键展开看全部；不提供「一键上屏提示内容」。
- **全本地**：用户包里带着记忆卡与关键词索引（云端打包时生成，含同义词扩展，弥补本地没有模型理解的不足），
  `HintIndex` 在内存里匹配，命中就显示，不联网。
- **切到对象时**：状态条旁一次性显示今日相关（「明天是她生日」「你答应的电影还没看」），提醒列表在包里按日期预先算好。
- 提示的点击 / 忽略记在本地，随下一批素材上传，用于云端调整卡片权重。

## 学习

| 层 | 在哪学 | 在哪用 | 学什么 | 数据范围 |
|---|---|---|---|---|
| 基础学习 | 本地（青简原有） | 本地 | 词频、用户词、n-gram、敲错表 | 全局；工作场景可只写不读其他场景 |
| 人设分区学习 | 云端 | 本地（人设包） | 这个用户在这个人设下的常用说法 | 只用本分区的脱敏数据 |
| 对象分区学习 | 云端 | 本地（用户包） | 和这个人聊天的常用词、记忆卡 | 只用本分区的脱敏数据 |

- 只有分区内部学习，没有跨分区、跨用户的第三层。分区之间不共享任何学习结果，包括同一用户的不同对象。
- 分区学习的产物是一份学习表（与本地 `FrequencyLearner` 同构），这样 Core 的叠加逻辑不需要区分来源。
- 为什么在云端学而不是本地学：脱敏、抽卡、同义词扩展需要大模型；学习表本身可以本地算，但统一在云端算能保证多台设备一致。

## 云服务接口

打字过程中不调用任何接口；下面都是后台同步或用户主动操作。

| 接口 | 何时调 | 输入 | 输出 |
|---|---|---|---|
| `POST /session/open` | 启动、联网恢复 | 账号令牌、解封后的 UMK | 会话 id |
| `POST /ingest` | 后台，上传队列非空时 | 分区 id、素材（已规则脱敏）、类型（发出 / 记一笔 / 提示反馈） | 202，异步学习 |
| `GET /packs` | 后台同步 | 本地各包的版本 | 有更新的包列表 |
| `GET /packs/{id}?from=<版本>` | 后台同步 | 本地版本 | 增量补丁或整包（DEK 密文） |
| `PUT/DELETE /cards/{id}` | 用户在管理界面改卡 | 分区 id、卡片 | 新版本号 |
| `POST /rewrite` | 用户按改写快捷键（可选功能） | 选中文字、分区 id | 1 到 3 条改写 |

- `/rewrite` 是唯一实时调用的接口，因为改写需要大模型；它由用户按快捷键主动触发，不在打字路径上，
  走与 `PredictionKind::Translate` 相同的「选中文字 → 快捷键 → 替换」链路，新增 `PredictionKind::Rewrite`。不开这个功能就完全没有实时调用。
- 客户端沿用 `qingjian-predict` 的做法：后台线程、超时、只信约定的格式。
- 模型供应商选签了零留存条款的；服务端日志只记接口名、耗时、token 数、脱敏命中计数，不记内容。

## 风控

素材与学习在云端，服务端能看到上传量与对象数，但数据也在你手里，责任更大。

- ~~每个场景最多 8 个对象~~（2026-10-05 取消：人数不限；每个场景可以自己挑 4 个置顶，键盘的选择面板先摆他们）。
- 一个账号同时在线设备 ≤ 2；对象与记忆不跨账号共享、不提供导入。
- 按账号限流（`/ingest`、`/rewrite`、`/packs`），超出直接拒绝，不卖加量包。
- 不开放 API、不做团队版。
- 只看计数与频率不看内容：对象频繁增删、素材量远超单人正常聊天、改写量远超输入量 → 冻结云功能并人工复核。
- 切换在本地发生，云端看不到切换频率；风控只能依据上传量与对象数，这是本地使用的代价。

## 收费与上架

- **免费**：基础输入（青简的拼音、词库、整句、本地学习），不登录、不开「完全访问」也完整可用；手动建对象、手动写记忆卡、本地提示行。
- **收费（订阅）**：云服务——素材上传、脱敏、每天的分区学习、抽卡与每周确认、改写。只有付费并主动开启记录的用户才上传任何数据。
- **只有一个 App**：记录的数据只在输入法自己的容器 App 里查看与管理，不做独立的记事本 App。App 里的内容都要回到键盘发挥作用（提示、候选、提醒），定位是「键盘记住的事」。
- **审核要点**（App Store 审核指南）：4.4.1 键盘不开完全访问也能用、采集的数据只用于增强键盘功能；5.1.1 采集前取得同意、可随时撤回、App 内可删除账号；
  5.1.2 写明交给哪家第三方大模型并单独取得同意；3.1.1 App 内售卖订阅走苹果内购。Android 走 Google Play 的显著披露与结算政策，国内渠道另做个人信息合规检测。

## 隐私与合规

- 云端保存的记忆卡含第三方（聊天对象）的个人信息，按个人信息保护法处理：单独同意、可查阅可删除、最小必要。
  服务器在新加坡，登录前单独取得出境同意，见 [sujian-encryption.md](sujian-encryption.md)「数据存储地」。
