# 打的字要不要进素材（设计草稿，只写不做）

**问题。** 用户说「现在输入的记忆也还没有自动变成卡片」。排查（2026-10-10）的结论是：**打字根本不产生素材**——
键盘里唯一的素材写入接口 `qj_memory_note` 只被「记一笔」调用（`cloud/ios/Keyboard/Sources/KeyboardModel.swift` 的
`saveNote`，剪贴板确认条与手写两条路），打字走的是输入日志与本地学习。所以 learner 开着也没用：没有东西可整理。

这份草稿只回答「要不要让打字也变成候选素材」，**只写不做**。

## 三条先摆出来的硬约束

1. **iOS 键盘拿不到宿主 App 的身份。** 键盘扩展的 API 不暴露宿主的 bundle id，`[apps]` 分节（`qingjian-platform`
   的 `AppsConfig`）在 iOS 侧没有任何人读——Mac 壳才用得上。所以「只在聊天类应用里采」这个过滤条件**在 iOS 上做不了**，
   只能用键盘自己知道的两件事：**当前对象已选定**、**不在私密输入框**（`textContentType` 那条路已有）。
2. **提示命中是「和这个人有关」的最强信号。** 提示行只在用户已经为这个人写过卡、且卡片命中当前输入时才出
   （`hint` 与 `cardId` 都在手上）。
3. **隐私两条用户必须知情**：数据存在新加坡、整理时经新加坡发往中国境内处理、DeepSeek 可能保存数据或用于改进
   它的模型。现有同意页（`App/Account/ConsentSheet.swift`）已经写了这两条。

## 方案 A：留在本机当候选，每周确认一次再上传（推荐）

**采什么。** 当前对象已选定 + 非私密输入 + 这次上屏**命中过这个人的提示**时，把上屏的那句话留在本机
（`<user_dir>/memory/pending-<contact>.jsonl`，沿用 `memory/` 的完全访问与数据保护级别），**不上传、不进同步**。

**什么时候变成素材。** 攒到一定条数或每周一次，在 App 里给一次「这周值得记的吗？」的列表，用户逐条勾选
（可全选、可全跳过）；**勾中的才进 materials、才走现有脱敏与上传**（仍要「云端记忆」那个开关开着）。

| | |
|---|---|
| 隐私边界 | 没勾之前**不出本机**；勾了之后才走现有链路：本机抹掉姓名/电话/地址 → 上传（新加坡）→ 整理时发往中国境内。两条知情点不变，但同意页那句要改写（见下） |
| 用户要点几次 | 日常 **0 次**；每周一次勾选（不愿看可以全跳过）。不点就没有，不会自己跑 |
| 出卡大概几天 | 勾选当天上传 → learner 当天或次日那一跑整理 → 卡同步回手机：**次日到 2 天** |
| 与同意页的关系 | **要加强一句**。现在写的是「记下的素材先在本机抹去姓名…再上传」；要改成「键盘会在你和这个人聊天时，把命中记忆卡的那句话留在**本机**，你每周确认之后才上传」——把「先本机、后确认」这两步说出来 |

## 方案 B：脱敏之后直接自动上传

**采什么。** 同 A 的采集条件，但命中即上传（脱敏仍在客户端做，规则与现在一致）。

| | |
|---|---|
| 隐私边界 | **没经过用户逐条确认，句子就离开了手机**。同意页要说清「键盘会自动把你打的句子（脱敏后）上传」——比现在重一档 |
| 用户要点几次 | **0 次**（只有一次总开关） |
| 出卡大概几天 | 当天打完 → learner 当天跑 → **次日**（比 A 快一天） |
| 风险 | 聊天里出现的**别人的**隐私（对方的话、地址、号码）也会被采进去。脱敏那套在模型层验到漏检 ≤5%（`docs/superpowers/evals/2026-10-05-deid-hard-deepseek.md`），但规则层仍有误漏；出问题时用户没有「事前拦一道」的机会 |

## 推荐：先做 A

出卡只慢一天，但把「谁的话可以离开手机」这个决定留在用户手上——这类产品最难挽回的就是这一条。B 的失败模式
（把对方没同意的东西传上去）代价远大于快一天。
A 跑稳之后，如果确认率很高（比如大多数人每周都点全选），再给一个「以后别问了，直接传」的开关——那等于 B，
但是用户自己选的，而不是替他决定。

## 落地要点（只列，不做）

- **存哪**：`<user_dir>/memory/pending-<contact>.jsonl`；不进同步、不进上传队列、不受 200 条素材上限（另给一个，
  比如 200 条候选就停下来提示去确认）。
- **谁写**：桥侧（键盘只调），与 materials 同一套切段与上限规则。
- **判定**：先只用「上屏那句包含命中卡的关键词」，不做向量相似度。
- **每周那一次**：放 App「记得」页顶部一条，或「我」页一个入口；**不做推送**。
- **与「记一笔」的关系**：不替代。记一笔是用户主动、立即上传的强信号；这条是弱信号 + 事后确认。
- **开关**：`[memory] typing_candidates`（缺省开还是关，交用户定；缺省关的话，这个设计对现状没有影响）。

## 要产品定的三件事

1. 做不做（做完 A 再看要不要 B）；
2. 每周确认的入口放哪、多久一次；
3. 采集开关缺省开还是缺省关。
